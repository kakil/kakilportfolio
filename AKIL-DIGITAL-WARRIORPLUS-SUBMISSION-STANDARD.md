# Akil Digital WarriorPlus Product Submission Standard

**Status:** Active reusable operating guide  
**Last reviewed against WarriorPlus documentation/live UI:** October 1, 2026  
**Applies to:** Akil Digital products submitted through WarriorPlus

---

# 1. Purpose

This guide preserves the field-by-field decisions and lessons that repeatedly matter when creating a WarriorPlus product and offer.

It is intended to prevent future launches from having to rediscover:
- which product fields require real values,
- which temporary notes are acceptable while building a shell,
- what must be replaced before compliance submission,
- how to describe AI use truthfully,
- what evidence should be captured,
- which fields must never be invented.

WarriorPlus can change its UI and requirements. Recheck the live interface and current WarriorPlus Help Center before each launch.

---

# 2. Product General Information

## Product name

Use the exact commercial product name. Keep the spelling and year/version consistent across:
- WarriorPlus,
- sales page,
- delivery page,
- JV page,
- support material,
- repository documentation.

## Categories

Choose categories that truthfully describe what the customer is buying, not merely topics that may appear inside the product.

When the live UI permits multiple categories:
1. choose the most accurate broad primary category,
2. add only genuinely relevant secondary categories,
3. do not select AI, ChatGPT, software, affiliate marketing, or another high-interest category merely for exposure if the product is not substantially about that subject.

Record the exact saved categories in the project training capture because WarriorPlus category choices can change.

## Content type

Choose the format the customer is actually purchasing.

Examples:
- research/report delivered primarily as a document → ebook
- hosted software product → software (online)
- downloadable application → software (download)
- gated member area → website / membership
- service/consulting engagement → service

Do not label an information product as software merely because AI or web tools were used to create it.

---

# 3. Product Access

WarriorPlus currently asks for product-access information such as a download file, access URL, and admin access information.

## Access URL

Use the real customer delivery/access page.

Do not invent a live URL that does not exist.

If the final delivery page is still being built:
- record the planned URL in project documentation,
- create and test the page before compliance submission,
- replace any temporary setup value with the real delivery location before review.

## Admin Access Info

This field may be required even when the product does not use a login.

If no login is required and the product is still in shell setup, use a truthful reviewer note rather than fake credentials.

Reusable temporary wording:

> No login is currently required. This product is a downloadable digital product. A dedicated product access/review URL will be provided before WarriorPlus compliance submission.

Before submission:
- update this text if the delivery model changes,
- provide reviewer login instructions if login becomes necessary,
- verify that the reviewer can actually access the product.

Never put passwords, API keys, payment credentials, or other secrets into the repository/training documentation.

---

# 4. AI Disclosure

If AI materially assists in creating the product, disclose that use plainly. Do not describe the product as wholly human-created if AI materially contributed, and do not imply that AI-generated material was independently verified merely because a model produced it.

Reusable Akil Digital disclosure for research/information products:

> AI tools are used as assistive tools during the research, organization, analysis, drafting, and editing process. Akil Digital is responsible for selecting the opportunities or subject matter, reviewing source material, interpreting evidence, making product recommendations, and editing the final product. AI-generated output is not treated as independently verified evidence, and factual claims are checked against cited or otherwise documented sources where applicable.

Adapt the wording to the actual product. For example, software products may instead disclose AI assistance in coding, documentation, design, or testing.

The disclosure must describe the real workflow. Do not use a generic disclosure that overstates human review or verification that did not occur.

---

# 5. Licensing, Refunds, Support, and Ownership

## License

Select the actual customer license. Do not guess merely to save the shell.

## Refund / guarantee

Enter the commercial refund period promised on the sales page and throughout the funnel.

The refund statement on WarriorPlus and the sales copy must not conflict.

## Support

Use a real support email or support URL.

Do not invent a support address merely to complete setup.

## Ownership / certification

Only certify ownership/distribution rights that Akil Digital actually holds.

---

# 6. Pricing and Affiliate Settings

Enter the actual commercial values from the frozen offer architecture.

Capture:
- launch price,
- post-launch price if applicable,
- payment structure,
- commission,
- merchant account actually selected,
- any recurring billing/cancellation settings.

Do not confuse a planned future price with the currently active checkout price.

---

# 7. Offer Dependency

A WarriorPlus Product by itself is not the complete sellable/reviewable structure.

Typical dependency:

```
Create Product
      ↓
Create Offer
      ↓
Attach Product to Offer
      ↓
Configure Sales Page / Availability / Affiliate Program
      ↓
Submit completed Offer for review
```

For affiliate recruitment, the canonical affiliate signup/request URL is generated at the Offer level.

---

# 8. Offer and Compliance Review

Before submitting the offer for approval, verify:
- sales page URL is real and correct,
- delivery/access URL works,
- reviewer access instructions work,
- support/contact route is visible,
- privacy policy is present when required,
- product content matches the sales copy,
- proof is real,
- scarcity is real,
- refund language is consistent,
- required WarriorPlus sales-page/buy-button/disclaimer code is installed,
- product and offer are connected correctly,
- affiliate settings are intentional.

WarriorPlus guidance reviewed October 1, 2026 states that product review occurs through the completed Offer workflow rather than by creating a Product alone.

---

# 9. Launch-Time and Approval Timing

WarriorPlus guidance reviewed October 1, 2026 states that offer launch times are entered in US Central time.

Always:
- convert the public marketing time to the time zone WarriorPlus currently requires,
- save it,
- reopen/verify the stored value,
- record both public and platform-entered times in the project log.

Current guidance also indicates normal review can take multiple business days and recommends submitting well ahead of launch. Treat approval lead time as a launch dependency, not a final-day task.

---

# 10. Evidence to Preserve

For every WarriorPlus product submission, record in the project repository:
- Product ID,
- Offer ID,
- exact product name,
- exact categories,
- content type,
- access URL,
- admin/reviewer access wording,
- AI disclosure wording,
- license,
- refund period,
- support route,
- pricing,
- commission,
- merchant account selection (name only; no credentials),
- affiliate approval rules,
- affiliate signup URL,
- public/private state,
- launch/close time as saved,
- approval submission date,
- approval status,
- compliance revision notes,
- screenshots of important setup states,
- test purchase and delivery result.

Never preserve payment credentials, passwords, tokens, or secrets.

---

# 11. Shell Setup Rule

A temporary shell may use honest descriptive text where WarriorPlus requires a field before the final asset exists.

Acceptable temporary information must:
- be truthful,
- clearly state what is not yet required/available,
- not impersonate a working credential or URL,
- be replaced before compliance submission if it no longer describes the final product.

Do not use fake customer access, fake reviewer credentials, fake proof, fake testimonials, fake scarcity, or invented contact information.

# 13. Affiliate Program screen

WarriorPlus offer setup may include:
- Affiliate Program ON/OFF
- General Information
- Program Details URL
- Affiliate Contact Email
- Affiliate Updates List
- Affiliate Program Accelerator
- Allow New Requests
- Auto-Approval

Reusable setup rules:
- turn the Affiliate Program ON when the offer is intended for affiliate promotion,
- use General Information for a concise affiliate-facing summary, launch date, and commission facts,
- use Program Details URL for the real external JV/affiliate page only after it is live,
- use only a real configured contact email,
- do not connect an affiliate update list unless an intentional email integration exists,
- leave promotional/accelerator features off unless deliberately chosen,
- prefer manual affiliate approval initially unless the vendor intentionally changes the policy,
- verify the actual global-account behavior when using “Use Default.”

For Digital Opportunity Intelligence 2027 on October 1, 2026, the live account showed:
- global setting: allowing new affiliate requests,
- global auto-approval: disabled.

Those account-specific values are not universal defaults for future products.
